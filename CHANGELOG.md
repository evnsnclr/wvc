# Changelog

User-visible changes, newest first. Releases are git tags `vX.Y.Z`: CI publishes a tag to PyPI after the checks pass, and a tag must name a section here.

## Unreleased
- `wvc diff` pairs tensors across a rename (spec section 2): a tensor present under one name only is paired by id (same bytes, dtype, and shape) and then by a leading name prefix (same dtype and shape; `language_model.`, `base_model.model.`, or `model.` added or dropped), only when the pairing is unambiguous. A paired tensor is `unchanged` or `changed` with the usual statistics, listed under its name in a with `renamed_to` its name in b; the summary gains `renamed`, the table writes `name -> new name`, and the agent view and `wvc classify` count renames (a renamed but identical upload is a `reupload`). Every `added` and `removed` entry now carries `sha256`, its id. The diff record has no format label; the new fields are additive, and the safetensors manifests are unchanged. The conformance vectors gain the renamed pair `wrap-a`/`wrap-b` and `wrap-diff.json`; `diff.json` and `quant-diff.json` gain `summary.renamed` and the ids.
- `wvc classify` says what kind of change a diff shows (`reupload`, `quantization`, `direction-removal`, `direct-edit`, `merged-lora`, `dense-finetune`, `mixed`, or `unknown`), with a `strong` or `weak` tier, the rule that fired, and the evidence. It reads a diff JSON record or two checkpoints; `--features` reads the changed tensors again to measure their rank against the rounding floor and whether the layers share one direction. `wvc diff --classify` appends the result to the record and the table. The rules and thresholds are in `docs/classification.md`; rules `v2` also read GGUF quantization comparisons, where changed norms make a quantization `mixed`.
- `wvc hash`, `wvc diff`, and `wvc verify` read a GGUF file on the Hub as `hf:OWNER/NAME[@REVISION]:FILE.gguf` (spec section 5.5): it is fetched like a safetensors shard and its SHA-256 is checked against the Hub's listing. Naming any part of a split file (`NAME-00001-of-00003.gguf`) reads every part as one checkpoint, after checking that their `split.*` keys agree; a missing or disagreeing part is refused. A bare `hf:` argument on a repository of GGUF files exits 2 and lists them with their sizes. A quantization comparison with a Hub side says which files, commits, and file types (`Q4_K_M`) it compared.
- `wvc hash`, `wvc diff`, and `wvc verify` read GGUF files (version 3). A GGUF tensor's id is the SHA-256 of its stored, possibly quantized bytes, its manifest `dtype` is its ggml type (`Q4_K`, `Q8_0`, ...), and `wvc hash --format gguf-hash` prints what `llama-gguf-hash --sha256` prints. Headers are checked against llama.cpp's rules before anything is allocated. `commit` refuses a GGUF file by name.
- `wvc diff` of a GGUF file against a safetensors checkpoint is a quantization comparison: names are mapped back for the `llama`, `qwen2`, `qwen3`, `gemma3`, and `phi3` architectures (others are refused by name), llama's q and k permutation and Gemma 3's added 1 are undone, and tensors whose bytes cannot be compared are compared by exactly dequantised values (F32, F16, BF16, Q4_0, Q4_1, Q5_0, Q5_1, Q8_0, Q4_K, Q5_K, Q6_K, Q8_K). The JSON record gains a `comparison` object, a `gguf` object per GGUF side, and per-tensor `compared`, `name_a`/`name_b`, and `transform_a`/`transform_b` fields; records of two safetensors checkpoints are unchanged.
- `wvc diff --format agent` prints a compact Markdown report for LLM agents, the stable format `wvc-diff-agent/0` (spec section 2.2): the pair, the headline counts, changed tensors grouped by projection and by runs of layers, the largest changes, added, removed, and reshaped tensors, and what a diff does and does not show. `--format json` is `--json`. [docs/agents-reading-diffs.md](docs/agents-reading-diffs.md) says how to read both.

## 0.1.0
- Hardened against hostile input before this first release, following two rounds of code and security review: a checkpoint, store, or remote controlled by someone else can make wvc refuse, never write outside the directory you named, run code, or report bytes as verified that are not. What it refuses, and why: tensor records above `max_tensor_bytes` (16 GiB by default, 1 TiB at most) and frames that do not match their record, so a kilobyte store cannot claim gigabytes; shapes over 64 dimensions and headers with more brackets than tensors could need; non-regular input files and symbolic links out of a checkpoint; remote files larger than their records imply; a stored object that does not decode back to its tensor id; `--force` replacing a file no earlier checkout wrote unless named with `--overwrite`; and values longer than 40 characters in any message. Checkouts check free disk space first and move existing files aside so a failed rename restores them; every wvc error exits 2, a bug propagates as a traceback, and `WVC_DEBUG=1` re-raises. The documented limits are in `SECURITY.md`.
- First release: `hash`, `diff`, and `verify` on local and Hub checkpoints; repositories with `init`, `commit`, `log`, `show`, `checkout`, and `fsck`; `bisect`; `merge-adapter`; `card`; `remote`, `push`, `pull`, and `clone`; spec v0 with conformance vectors under `spec/vectors/v0`.
- `wvc --version` prints the version.
- A `v*` tag on a `main` commit publishes the sdist and wheel to PyPI through trusted publishing (`.github/workflows/release.yml`), after the tag is checked against the project version and this changelog, the checks pass on Ubuntu, and the sdist is checked to hold only the package, tests, conformance vectors, and top-level documents.
- `wvc diff --rank` estimates the rank of touched blocks up to 2^26 elements, so a 9B-class projection matrix gets a rank without `--rank-cap`. The block is decoded to float64 and copied twice, so a block at the cap peaks near 1.1 GiB of memory and can take about 20 s.
- `wvc hash`, `wvc diff`, and `wvc verify` accept a Hub repository as `hf:OWNER/NAME[@REVISION]` (install the `hf` extra); a diff of two Hub repositories fetches only the shards whose Hub hashes differ and reports the rest unchanged from their headers.
- `wvc hash --format gguf-hash` prints llama.cpp gguf-hash manifest lines for a safetensors checkpoint.
